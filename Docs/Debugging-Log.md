# 调试日志

记录可复用的故障证据、排查顺序和验收边界；不是发布记录，也不把单元测试通过当作实机恢复。

## 2026-11-04 — L/ZL 输入丢失导致语音失效

**检索词：** Joy-Con、L、ZL、L3、语音输入、听写、无反应、HID、`0x30`、`0x3F`、辅助功能、`Ctrl+Shift+D`。

### 结论与当前状态

- 本次已确认根因在输入端：`LeftJoyConHIDAdapter.handleInputReport` 原先只从完整报告读取电量，没有解析 L/ZL/L3；这些按键仍依赖可能不产生事件的 HID element-value 回调。
- 实机原始流是带 report ID 的 **49 字节 `0x30` 完整报告**。用户分别按 L、ZL 时，左按键字节出现 `00 → 40 → 00 → 80 → 00`，证明这次两个实体键及蓝牙上报正常，不能归咎于硬件损坏。
- 0.3.4 补充完整/简单报告解码，并把报告与旧 element-value 回调合并成单一、去重的按下/松开状态；命令回复 `0x21` 不作为按键状态来源，防止旧快照中断按住；断连释放已按下的输入。
- **0.3.4 已安装，用户确认“可以了，没问题了”，并明确确认“L 语音已恢复”。** 自动验证为 143 项测试、构建/签名/压缩包校验及回滚验证通过。原配置保留。
- 本轮未独立逐项复测 Claude 双输入框、右 Joy-Con、ZL 三连切换及全部重连场景，不把这次确认扩展成这些场景全部通过。

### 为什么这类问题容易反复出现

没有统计过发生频率，不能断言每次都是同一根因。共性是多层兼容链路把不同故障表现成同一个“没有反应”：

```text
实体键 → 蓝牙报告 → HID 补充输入 → 映射/Fn → 前台目标与权限 → 输出事件 → 应用录音/转写
```

| 风险点 | 本次证据与应对 |
| --- | --- |
| 同一手柄有两条输入路径 | 摇杆/方向键经 GameController 正常，不代表依赖 HID 补充路径的 L/ZL 正常。L、ZL 同时失效，应先查共同输入通道。 |
| 报告模式与回调假设不一致 | `0x30` 报告已到达，旧代码却只读电量；既有 usage 15/16 测试覆盖不了“根本没有 element 回调”。需要用真实报告回放测试。 |
| 外部应用的界面接口会变化 | Codex 扫描实际只有 12 个外壳节点，网页/输入框均为 0；根据打包代码里的按钮文案推断可通过 AX 点击，并不成立。Claude 输入框标签也有变化，但不能据此解释 L/ZL 的共同输入丢失。 |
| 快捷键存在多个注册层 | `composer.toggleDictation` 的浏览器绑定，不代表桌面原生全局听写不存在。用户实际配置的 `globalDictationHotkey=Ctrl+Shift+D`，且物理键盘实测可用。不要只看一个命令定义就下结论。 |
| 诊断信息被后续输入覆盖 | Feedback 很快变成摇杆事件，无法据此断言此前没按 L。短时探针结束后才收到用户确认，也不能当作“没有原始报告”的证据。现保留语音诊断、报告模式和 L/ZL 按下计数。 |
| 升级权限与功能故障叠加 | ad-hoc 签名变化后需核对新进程的辅助功能授权；已授权也不代表输入、AX 或录音可用。权限恢复是安装检查，不是本次最终根因。 |
| 运行包与 checkout 不一致 | Git 干净、测试通过、构建成功都不能证明当前安装包来自这份代码，或真实按键已恢复。先核对运行路径、版本与哈希。 |

### 本次排查中的纠偏

1. 前几轮先改了输出端的 AX 标签识别、界面准备及原生快捷键，未先证明 L/ZL 已到映射层；安装和测试通过后，实机仍失败。
2. “`Ctrl+Shift+D` 仅浏览器可用”的早期判断不准确。用户物理键盘验证推翻了它；桌面全局听写配置必须单独核对。
3. “最近一次输入不是 L”不等于 L 未到达，必须结合持久计数或完整采集时段判断；后来的原始报告才锁定输入端漏解析。
4. 最终成功依据是 **原始输入证据 + 报告回放回归 + 新版安装校验 + 用户实机确认**，不是测试数量或“事件已发送”。

### 下次排查：按顺序找第一个断点

1. **冻结运行对象。** 记录安装包版本、运行路径、二进制 SHA-256、源码位置、目标应用及 Test Mode。不要从目录名或 Git 状态推断运行版本。
2. **先看输入。** 在控制器窗口分别按 L、ZL，观察 `L/ZL 输入诊断` 的报告类型、状态和累计按下次数。两个都不增加时先查 HID，不先改录音按钮。
3. **必要时抓原始报告。** 记录采集开始/结束及用户动作是否发生在采集期间；核对 report ID、长度、是否包含 ID、按键位和释放。完整报告的 L/ZL 位分别是左按键字节的 `0x40`/`0x80`，只解析补充控制，不重复输出 GC 已拥有的方向键/SL/SR。
4. **再看映射。** 确认 `Left Shoulder` 的 hold 动作、`Left Trigger` 的 Fn 状态；ZL 单按本来不会录音。检查重复按下、双来源去重、松开、断连与切换清理。
5. **最后查输出与目标应用。** 核对实际前台目标、权限、持久语音诊断。先由用户分别验证鼠标麦克风、物理键盘原生快捷键；AX 没暴露控件时不要凭坐标猜按钮，也不要把“找不到按钮”归为手柄坏了。
6. **分层验收后再说完成。** 协议/状态测试 → 控制器实时按键计数与映射 → 目标应用实际录音、松开停止及转写。修复中检查受影响测试，代码候选按维护策略做最终检查；文档变更不重装应用或重置权限。

只读运行身份检查（JoyRelay 0.3.7 起的安装路径；旧版使用 `JoyConUnifiedController.app`）：

```sh
APP=/Applications/JoyRelay.app
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "$APP/Contents/Info.plist"
pgrep -x JoyConUnifiedController | xargs -n1 ps -o pid=,command= -p
shasum -a 256 "$APP/Contents/MacOS/JoyConUnifiedController"
codesign --verify --deep --strict "$APP"
```

### 回归结果与证据定位

同一组 `0x30` 报告回放：**BASELINE（0.3.3）无按键事件 → MODIFIED（0.3.4）产生 L 按下/松开、ZL 按下/松开 → ROLLBACK 恢复无事件，源码哈希复原**；验证后已重新应用修复。另有去重、Fn 顺序、模式切换、显式无头报告、无效报告及断连状态重置的单元回归，不等于全部连接场景的实机测试。

**源码与发布边界：** 这次事件的历史基线是 `5f8b2d3`。修复已经并入
JoyRelay 0.3.7 开发源码；此前本机的 0.3.4 实机验证不等同于新版本发布，
也不等同于 Switch Pro 语音验收。原始采集、安装收据及回滚包只保留在维护者本机，
不随公开仓库分发。
